# `ctg zk` Reference

Circom Groth16 helpers for Soroban. For concepts and configuration, see the [ZK Overview](/docs/zk/overview); for a walkthrough, the [ZK Tutorial](/docs/zk/tutorial).

<Callout type="warning">
  `ctg zk *` is **experimental** and outside the v3 stability contract.
</Callout>

`[circuitName]` is optional on `build`, `prove` and `invoke`; when omitted, the first circuit in `zk.circuits` is used. Artifacts land in `.artifacts/zk/<circuit>/`.

## `ctg zk init [projectName]`

Scaffolds a ZK project, or adds ZK to the current project when `projectName` is omitted inside a directory with `caatinga.config.ts`.

| Flag | Description |
| :--- | :--- |
| `-t, --template <template>` | Template to copy. Default: `zk-starter`. |
| `--minimal` | Minimal identity circuit and verifier, no template copy and no frontend. |
| `--force` | Overwrite existing `circuits/main.circom` and `contracts/verifier`. Without it, `init` stops if they exist. |

In an existing project, `zk init` needs `npm install` to have run (it loads `caatinga.config.ts`; any load failure is reported as `No caatinga.config.ts found`). It merges a `verifier` contract and a `zk` block into `caatinga.config.ts`. New artifacts files are written with schema `version: 2`. If the merge fails — for example because a `zk` block already exists — the command prints the blocks to add by hand and exits with code 1.

<Callout type="warning">
  Known issues in 3.12.0 when adding ZK to an existing project: the default mode does not copy `contracts/verifier`, and the config merge can produce invalid TypeScript after a contract entry without a trailing comma. Verify both after running it. See the [ZK Tutorial](/docs/zk/tutorial#1-scaffold-the-project).
</Callout>

```bash
npx ctg zk init my-zk-dapp           # new zk-starter project
npx ctg zk init my-zk-dapp --minimal # headless
cd my-app && npx ctg zk init         # add ZK to an existing project
```

## `ctg zk build [circuitName]`

Compiles the Circom circuit (`-p bls12381`) and runs a single-party dev trusted setup. On first use, downloads and checksum-verifies Circom and snarkjs into `~/.caatinga/zk-tools`.

| Flag | Description |
| :--- | :--- |
| `--embed-vk` | **Experimental.** Also writes `contracts/verifier/src/vk.rs` from `verification_key.json`. Not usable end to end yet. |
| `--allow-dev-ceremony` | Allow the dev ceremony when `defaultNetwork` is mainnet. Not for production. |

Fails with `No ZK circuits configured in caatinga.config.ts` when the `zk` block is missing or empty.

## `ctg zk prove [circuitName]`

Generates `proof.json` and `public.json` from `circuits/input.json`, using the WASM witness generator produced by `zk build`.

| Flag | Description |
| :--- | :--- |
| `--debug` | Also emit `witness.wtns` for inspection. |

`input.json` must hold private signals only; a public output there fails with `CAATINGA_COMMAND_FAILED` (hint: `Too many values for input signal <name>`).

## `ctg zk invoke [circuitName]`

Serializes the proof, verification key and public signals and calls `verify_proof` on the circuit's `verifierContract` (dynamic VK).

| Flag | Description |
| :--- | :--- |
| `-s, --source <identity>` | **Required.** Stellar CLI identity that signs (e.g. `alice`). |
| `-n, --network <network>` | Configured network. Default: `defaultNetwork`. |
| `-y, --yes` | Confirm mainnet transactions without the interactive prompt. |
| `--allow-dev-ceremony` | Allow dev-ceremony artifacts on mainnet. Not for production. |
| `--embed-vk` | **Blocked** — the embedded-VK path is not supported end to end yet. |

Requires `verifierContract` on the circuit; otherwise fails with `Verifier contract not configured for circuit "<name>"`. On mainnet, the confirmation prompt and `[MAINNET GUARDRAIL]` audit log apply as for `ctg invoke`.

```bash
npx ctg zk invoke main --network testnet --source alice
```
